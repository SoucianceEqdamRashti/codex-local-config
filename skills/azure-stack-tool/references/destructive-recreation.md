# Destructive Azure Deployment Stack recreation

Use this reference when the requested change requires deleting stack-owned resources and deploying a fresh replacement. Use the normal stack preview workflow for in-place updates. A resource-group deletion is a different operation with its own scope and authorization.

## Preflight and review

1. Read the live tenant, subscription, resource group, stack ID, provisioning state and full managed resource IDs. Build separate reviewed inventories for deletion and preservation. Include unmanaged descendants that may be deleted with a managed parent, shared or cross-scope dependencies, provider-created resources, and soft-deleted names. Include expected data loss, downtime, endpoints and whether a recovery or backup is required. Keep the execution and journal resources outside the deletion scope.
2. Preview the intended replacement against the expected post-delete state and run provider and region checks. Check Azure Policy, feature registration, quota and usable capacity for the complete replacement. Verify the real executor's role assignments, scopes, conditions, deny assignments, and permission to remove any reviewed role assignments. A preview under an operator identity or with ProviderNoRbac leaves executor authorization unverified. Where practical, test critical data paths on a representative pilot before cutover, including an authorized runner for private endpoints.
3. Present the reviewed source inventory and replacement as one plan. Bind approval to the exact scope, full deletion and protected inventories, compiled replacement and its parameters or immutable revision and digest, expiry, and intended executor. Identify approvals for any additional actions, such as permanent purge of a soft-deleted service record. If required by the workflow, acquire the existing target lease and validate the approval receipt through the executor. Treat a lease as coordination among participants. An inherited privileged Azure role may still permit direct ARM writes.
4. Immediately before submission, refresh the live inventory, effective permissions and replacement preview under the same execution controls. Obtain renewed approval if the approved scope, payload, or plan changes materially. Resolve unknown deletes, protected-resource overlap, or insufficient replacement capacity before dispatch.

## Delete, reconcile, and replace

1. Use the Deployment Stack resource-only deletion action (`deleteResources`) when the approved plan preserves the resource group. Keep group-wide deletion, detaching, or permanent purge tied to their own explicit scope. Capture the exact target and operation intent before submission, then retain the Azure operation ID, request ID or status URL and result in the execution journal when available.
2. Poll Azure to terminal status. If the command times out or response parsing fails, inspect the operation, stack state, and live resources before resubmitting. Verify that every reviewed deleted ID is absent and that protected resources still exist. Compare active inventory with the review to find provider-created leftovers. Report soft-deleted records separately where they matter to names, recovery or dependency cleanup.
3. If a dependency blocks deletion, identify its provider, resource and error from Azure. For Foundry with a delegated agent subnet, a soft-deleted account can retain the service association link. Follow current Foundry cleanup guidance, check authorization for purge, and confirm the service-managed link has cleared asynchronously before retrying network deletion. If the link persists after purge and applicable lock checks, use Azure support. Never manually remove the provider-managed link.
4. Refresh the replacement what-if after confirmed deletion. Compare it with the approved plan and obtain renewed approval for material changes. Deploy with the approved inputs through the stack workflow. Reconcile stack membership and the Azure operation result, run a fresh convergence preview, and verify the actual workload from the intended network and identity. Include cleanup of temporary runners or grants in the result.
